# 흙별 낚시 S1 · 도래 낚시터

`낚시 실장 구상 v0.4`(여울, 2026-11-25)의 **제작 순서 A**를 v44 후보 빌드 위에 얹은 작업입니다. 기존 3종을 대상으로 **자리 고르기 → 그림자 반응 읽기 → 감고 쉬기 → 결과 확인**까지 동작합니다.

처음에는 잔빛숲 강변(X61~68)에 만들었습니다. 이후 알돌 결정에 따라 실제 위치를 **마을 '낚시터 입구'로 들어가는 전용 낚시터 `fishing_01`(도래 낚시터)**로 옮겼습니다. 숲 강변은 `RIVER_FOREST_BANK=false`로 꺼 둔 조작 비교용 코드입니다.

이 브랜치는 로컬 빌드·로컬 QA까지만 진행했습니다. PR 병합과 운영 배포는 하지 않았습니다. 수치는 모두 첫 튜닝값이고, 재미나 밸런스를 검증한 결과가 아닙니다.

## 빌드

```bash
bash tools/farm-cooking-b/build.sh dist/fcb          # v44 기본 후보, 낚시 S1 포함
node tools/farm-cooking-b/serve.mjs dist/fcb/fcb-main.mjs 8790 --assets dist/fcb/assets
```

`build.sh`의 v44 경로에서 광산 온보딩 패치 다음에 `tools/fishing-s1/patch.py`를 적용합니다. 다른 base(v41/v39/v38)에는 적용하지 않습니다.

## 힘겨루기 규칙

진도('발밑까지' 막대)는 **줄어들지 않습니다.** 열린 틈에 감을 때만 늘어납니다.

| 어종 | 단계 순환 | 감기에 필요한 틈 시간 |
|---|---|---|
| 은빛 피라미 | 틈 0.55~0.95초 → 파닥임 0.45~0.8초 | 2.4초 |
| 강농어 | 틈 1.1~1.7초 → 예고(몸 꺾기) 0.75초 → 돌진 0.9~1.3초 | 4.2초 |
| 비단잉어 | 풀림 1.9~2.7초 → 바닥 버팀 1.6~2.4초 | 5.4초 |

- **무입력:** 진도가 그대로라 끝까지 잡히지 않습니다.
- **계속 누르기:** 무리 값이 쌓입니다. 틈에서는 초당 0.2, 예고 중 0.35, 파닥임·돌진·버팀 중 0.75씩 오르고, 1에 닿으면 '정체'가 되어 감아도 진도가 멈춥니다. 손을 떼면 초당 0.9씩 줄고, 0.35 아래로 내려가면 회복합니다. 계속 누르기만으로는 끝까지 잡을 수 없습니다.
- **농어 돌진:** 돌진 동안 손을 떼고 흘려 보내면 다음 틈이 0.45초 길어집니다.
- 잉어 버팀 중에 감으면 릴만 헛돌고 모래가 일어납니다.

## 저장

`livingP0.river` 키를 새로 추가했고 `normalizeLivingP0` 허용 필드에 등록했습니다. 등록하지 않으면 복원할 때 버려집니다.

```js
river: {
  schema: 1,
  best:   { river_fish: 0, perch: 0, carp: 0 },   // mm, 0 = 크기 미기록
  spots:  { A: 0, B: 0, C: 0 },                   // 자리별 포획 수
  attempt: null | { id, fish, spot, size, progress }, // 걸린 물고기 (크기는 걸 때 확정)
  done:   [/* 최근 32개 시도 ID */],
  assist: false                                   // 자동 걸기 보조
}
```

- 기존 종 ID·`bag`·`fishDex`·`stats.fished`를 그대로 씁니다. 요리(`fish`)·판매·어부 납품 경로도 변경 없이 같은 재고를 씁니다.
- `river.hook`(보상 없음): 걸 때 종·크기를 확정해 저장합니다. 진행 중에는 진도 25%마다, 그리고 일시정지·닫기 때 저장합니다. 앱을 닫았다 다시 열면 같은 물고기가 정지 상태로 복원되어, 종료로 다시 뽑는 이득이 없습니다.
- `river.catch`(보상): 가방 +1, 도감, 통계, 최고 크기, 자리 수, 시도 완료를 한 번에 적용합니다. 시도 ID와 `done` 목록, 기존 `appliedIds`로 같은 시도의 중복 적용을 막습니다. 저장이 실패하면 상태 전체를 되돌리고 '다시 확정' 카드를 띄웁니다.
- 놓아주기는 보상 없이 `attempt`만 지웁니다.
- 예전 m17 낚시가 진행 중인 저장(`livingP0.fishing`)은 '이어서 끌어올리기'로 옮겨 가며, 진도는 이어받고 옛 필드는 지웁니다. 크기가 없는 예전 도감은 '크기 미기록'으로 보이고, 크기를 지어내지 않습니다.
- 옛 명령 `pond.cast/reel/slacken`은 순수 엔진에 남아 있지만, 생활 메뉴 낚시 탭에서는 버튼을 빼고 강변 안내로 바꿨습니다.

## 3D 렌더러 (2026-11-27)

유적(`ruins_3d_01`)과 같은 구조입니다. three.js r160은 이미 게임에 별도 스크립트로 들어 있어(`window.THREE`) 새 라이브러리를 추가하지 않았습니다. 모델·텍스처 파일이나 base64도 추가하지 않고 기본 도형만 씁니다.

| 항목 | 구현 |
|---|---|
| 좌표 | 낚시터 지도 x → three X, 지도 y → three Z, 높이 Y. 막힘·자리·출입구 판정은 2D 때와 같은 함수 |
| 장면 | 호수 분지(수면·바닥·둑), 선착장(B), 수초(A), 바위와 물살 줄(C), 나무, 서쪽 출입구, 자리 고리와 이름표, 물속 그림자 장식 |
| 플레이어 | 기존 걷기 시트(방향별 2048×256, 256 칸 8프레임)를 빌보드 스프라이트로 씁니다. 발 기준선은 칸 높이 6% 지점. 화면 기준 이동 방향으로 앞·뒤·좌·우 시트를 고릅니다 |
| 카메라 | 플레이어를 따라가는 원근 궤도 카메라. 화면 드래그 또는 Q·R로 회전, '⟳ 시점'으로 초기화. 들어올 때마다 출입구에서 호수를 바라보는 방향으로 시작 |
| 이동 | 조이스틱·방향키는 카메라 기준(유적과 같은 바닥 기준 축) |
| 성능 장치 | 그림자 없음, 안티앨리어싱 없음, 픽셀 비율 최대 1.5, `powerPreference:'low-power'`. 낚시 화면이 열려 있는 동안 3D 프레임을 그리지 않음 |
| 느린 프레임 | 기본 루프는 프레임당 45ms로 자르므로, 낚시터는 자체 실제 경과 시간(최대 0.25초)을 쓰고 0.05초 단위로 나눠 이동합니다. 느린 기기에서도 걷는 속도와 생활 시계가 실제 시간과 맞습니다 |
| 대체 | three가 없거나 생성에 실패하면 시작부터 2D, `webglcontextlost`면 2D로 전환. `fallback-probe.cjs`로 three를 숨긴 채 진입·낚시까지 확인 |

헤드리스 Chromium 프레임 시간입니다. 소프트웨어 GL이라 **실기기 수치가 아닙니다**. 같은 조건의 유적은 프레임 중앙값 567ms였습니다.

| 환경 | 중앙값 | p90 |
|---|---|---|
| 390×844 (DPR 3 → 렌더 1.5) | 42~46ms | 47~53ms |
| PC 1280×800 | 55~61ms | 65~79ms |

실기기(특히 Android 중저가)에서 프레임을 재야 합니다. `__sandstarFishingWorld.state().frameMs`가 최근 90프레임 중앙값·p90을 돌려줍니다.

## 남길 수량과 판매·요리 미리보기 (2026-11-28, 제작 순서 B)

v0.4 4절 '요리·농사·판매'의 권고입니다. 판매·요리 전에 '재료로 남길 수량'을 고르고, 소비될 종·수량·받을 C를 미리 보여줍니다. UI에만 보존이라고 표시하고 실제로는 소비하는 상태는 금지합니다.

**먼저 발견한 문제:** v44 마을(2.5D)에서는 생선·작물·요리를 팔 방법이 없었습니다. 생활 메뉴의 판매 버튼은 옛 횡스크롤 좌표(X23) 근처인지로 판단하는데, 2.5D 마을에서는 그 조건을 만족할 수 없어 버튼이 항상 꺼져 있었습니다. 바람장터에서는 광물만 팝니다.

| 항목 | 구현 |
|---|---|

### 힘겨루기 규칙 독립 검사 `fight-rules.cjs`

`river-flow.cjs`의 힘겨루기 규칙 항목은 물고기가 실제로 물어야 측정이 시작되므로, 유도 단계에서 입질이 오지 않으면 측정값이 빕니다. 지금은 세 번까지 다시 유도하고, 끝내 물지 않으면 원인을 로그에 남깁니다. 같은 규칙을 유도 운 없이 확인하려면 `fight-rules.cjs`를 씁니다.

- 어종마다 걸린 물고기(`river.attempt`, 진도 0)가 있는 저장을 타이틀 화면에서 만들고 다시 불러옵니다. 플레이어는 낚시터 B 고리 위에 서 있고, 행동 버튼으로 재개 카드를 연 뒤 실제 감기 버튼만 누르고 뗍니다.
- 기대값

| 항목 | 기대값 |
|---|---|
| 무입력 | 5초 동안 진도 변화 0 (정확히 같음) |
| 계속 누르기 | 10초 안에 정체. 정체 뒤 1초 더 눌러도 진도 변화 0 |
| 손 떼기 | 2초 동안 진도가 줄지 않음. 정체가 풀림(무리 값 초당 0.9 감소) |
| 포획 | 틈(gap/loose)이고 정체가 아닐 때만 누르면 결과 화면, 가방 +1, `attempt` 비움, 시도 ID가 `done`에 들어감 |

- 측정 예(PC): 피라미는 2.3초 만에 정체(진도 51), 강농어는 1.7초(진도 4), 비단잉어는 2.6초(진도 30). 포획까지 각각 2.4초, 9.1초, 7.9초
- 실행: `node tools/fishing-s1/qa/fight-rules.cjs http://127.0.0.1:8790/ <outdir> <pc|m390> [river_fish,perch,carp]`
